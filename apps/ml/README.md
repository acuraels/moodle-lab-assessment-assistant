# ML-сервис проверки лабораторных

Сервис принимает документы от существующего backend, извлекает текст и вызывает
Ollama по `OLLAMA_URL`. В текущей схеме backend и ML работают на Linux, а Ollama
на Windows доступна через Tailscale: `http://100.81.179.101:11434`. GPU на Linux
для этого не нужен. Запуск в Docker описан в
[инструкции развёртывания](../../docs/ml-deployment.md); ниже также приведён
вариант установки ML рядом с Ollama на Windows.
Файлы и результаты постоянно хранятся только в существующей PostgreSQL backend.
ML не подключается к БД и не получает пользовательские JWT.

Для текущей Windows-машины с 16 GB VRAM выбрана установленная модель
`freehuntx/qwen3-coder:14b`: на синтетическом наборе она дала лучший результат
среди проверенных вариантов. Ollama сообщила 10,05 GiB занятой VRAM при контексте
8192; это не конфигурация для 8 GB. Условия и ограничения сравнения приведены в
[отчёте оценки](../../docs/ml-grading-evaluation.md).

Значение конфигурации по умолчанию `qwen3:4b-instruct-2507-q4_K_M` сохранено как
**неизмеренный кандидат для будущей машины с 8 GB**. Его качество и потребление
памяти в этом проекте пока не проверены. Для текущего варианта явно задайте
`OLLAMA_MODEL=freehuntx/qwen3-coder:14b`.
Контекст по умолчанию 8192 токена, из них 2048 зарезервированы для ответа и 512 —
для шаблона сообщений. Только одна генерация выполняется одновременно.
Весь текст документа должен помещаться в контекст.

## Установка на Windows без Docker

Нужны Python 3.12, установленная Ollama и подключённый Tailscale. Из корня checkout
в PowerShell:

```powershell
cd apps/ml
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install ../../packages/assessment-contract
python -m pip install -e .
Copy-Item .env.example .env
```

Заполните `.env`; существующий файл не перезаписывайте. При использовании `ML_TOKEN`
задайте одинаковый секрет на ML и backend; это серверный токен, не JWT пользователя.

Перед стартом Ollama отключите облачные функции и параллельные генерации:

```powershell
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_NUM_PARALLEL = "1"
$env:OLLAMA_MAX_LOADED_MODELS = "1"
$env:OLLAMA_CONTEXT_LENGTH = "8192"
ollama serve
```

Команда `serve` занимает терминал. Если Ollama уже запущена в трее, сначала
завершите её, затем запустите с этими настройками. В другом терминале:

```powershell
ollama pull freehuntx/qwen3-coder:14b
ollama --version
ollama list
```

Загрузка весов требует Интернета только на этапе подготовки. Зафиксируйте версию
Ollama и ID установленной модели из этих команд в протоколе теста; проверка работает
локально и не скачивает модель автоматически. Ollama слушает loopback, наружу через
Tailscale доступен только ML-сервис.
В скопированной `apps/ml/.env` замените `OLLAMA_MODEL` на
`freehuntx/qwen3-coder:14b`; исходный пример содержит неизмеренный кандидат 4B.

Запуск ML из `apps/ml` с активным окружением:

```powershell
python -m uvicorn ml_service.main:app --host 100.81.179.101 --port 8001 --workers 1 --no-access-log
```

Tailscale должен быть подключён; указанный IP принадлежит Windows-машине в текущем
плане. Windows Firewall и политика tailnet должны разрешать Linux backend обращаться
к этому порту. Не публикуйте порт в публичный Интернет. Проверки:

```powershell
Invoke-RestMethod http://100.81.179.101:8001/health
Invoke-RestMethod http://100.81.179.101:8001/ready
```

Для `/ready` и `/evaluate` при заданном `ML_TOKEN` нужен заголовок
`X-ML-Token: <секрет>`. `/health` подтверждает работу процесса; `/ready` проверяет
доступность Ollama и наличие выбранной модели, **не** делает генерацию и не
подтверждает наличие свободной VRAM. Первый реальный документ проверяет загрузку
модели. Backend на Linux настраивается через `ML_URL` и `ML_TOKEN`; доступность
проверяется также из backend-контейнера, не только из shell хоста.

## Подсчёт контекста

Можно скачать **только tokenizer.json именно выбранной модели** (веса в
Python не нужны). Ниже пример только для кандидата Qwen3 4B, с файлом на ревизии
`1b4199c`; не подставляйте его для текущей 14B-модели:

```powershell
New-Item -ItemType Directory -Force C:/models/qwen3-4b-instruct-2507 | Out-Null
Invoke-WebRequest https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/resolve/1b4199c/tokenizer.json -OutFile C:/models/qwen3-4b-instruct-2507/tokenizer.json
```

В `apps/ml/.env`:

```dotenv
ML_TOKENIZER_PATH=C:/models/qwen3-4b-instruct-2507/tokenizer.json
```

Используется локальная библиотека `tokenizers`, без сетевых запросов во время
проверки. Токены содержимого сообщений считаются этим токенизатором; для шаблона
сообщений остаётся отдельный запас. При смене модели нужен соответствующий
токенизатор. Без файла применяется консервативный верхний предел: один UTF-8 байт
считается одним токеном. Такой режим безопасно отклоняет часть документов, которые
фактически поместились бы, особенно длинный русский текст. Превышение бюджета
возвращает `CONTEXT_TOO_LARGE`; скрытого обрезания или частичной оценки нет.
Сравнение моделей от 2026-11-08 выполнялось без локального токенизатора,
с консервативным подсчётом по UTF-8 байтам.

## Числовые критерии и качественная проверка

В существующем поле `grading_criteria` преподаватель может оставить обычный текст:
он будет использован для замечаний. **Числовая оценка в первом MVP разрешена только
при однозначной JSON-рубрике**, переданной текстом или файлом TXT/DOCX/PDF:

```json
{"criteria":[
  {"name":"Обработка пустого списка","max_score":4},
  {"name":"Корректное среднее арифметическое","max_score":6}
]}
```

Документ рубрики должен содержать именно этот JSON, без заголовков и пояснений.
Для PDF из извлечения убираются только служебные метки страниц; сложная вёрстка
может нарушить JSON, поэтому предпочтительнее текст или UTF-8 TXT. Также принимается
один блок ` ```json ... ``` `. Максимумы конечны, неотрицательны; сумма положительна,
названия уникальны. Обычные фразы «корректность — 6 баллов» автоматически в официальную
шкалу не преобразуются. Некорректный JSON также означает качественную проверку,
а не разрешение модели придумать шкалу.

Имена и максимумы критериев берутся из рубрики преподавателя, итоговые суммы
вычисляются кодом. При отсутствии корректной рубрики
возвращаются `score=null`, `max_score=null`, `criteria=[]`; в заключение код добавляет
явное объяснение отсутствия числовой оценки. Преподаватель принимает финальное
решение. Для произвольных естественно-языковых рубрик потребуется отдельное
согласованное извлечение/подтверждение шкалы.

### Как формируется числовая оценка

Внутренний ответ модели отделён от публичного API. Для каждого критерия в порядке
преподавателя модель сначала выбирает 1–3 цитаты из работы, затем пишет замечание
и определяет выполнение требования и балл:

```json
{"criteria":[{
  "criterion_index":0,
  "evidence":["if not values:\n    raise ValueError('empty')"],
  "comment":"Пустой список обрабатывается требуемым исключением.",
  "verdict":"met",
  "score":4
}]}
```

Сервис проверяет количество и порядок критериев, диапазоны баллов и согласованность
вердикта: `met` требует полного максимума, `not_met` — нуля, `partial` — значения
строго между ними. Каждая цитата должна встречаться в извлечённом тексте работы:
допускаются различия только в пробельных последовательностях; регистр, знаки
пунктуации и символы кода не исправляются приблизительным поиском. В комментарий
добавляются исходная цитата и номера строк **извлечённого текста**, а не номера
страниц документа. Переносы и отступы цитат сохраняются в интерфейсе.

Индекс заменяется именем и максимумом из преподавательской рубрики. Заключение
составляется кодом из проверенных баллов и вердиктов, поэтому его итог совпадает
с суммой критериев. Внешний ответ остаётся прежним: `score`, `max_score`,
`conclusion`, `criteria` с полями `name`, `score`, `max_score`, `comment`.
Внутренние `criterion_index`, `evidence` и `verdict` отдельными API-полями не выдаются.

Обычно выполняется одна генерация. Если JSON, цитаты или числовые ограничения
не прошли проверку, разрешена одна корректирующая генерация с безопасным кодом
ошибки. Повторная ошибка завершается `MODEL_INVALID_RESPONSE`, без фиктивной оценки.
Планового второго прохода для пересмотра валидной оценки нет.

**Совпадение цитаты подтверждает её источник, но не правильность трактовки.** Модель
может неверно понять даже реально процитированный код. Дополнительные правила
частичных баллов, написанные обычным текстом в методичке, передаются модели, но не
проверяются как формальная шкала: код проверяет диапазон и соответствие вердикту.
При качественной проверке без JSON-рубрики цитаты внутри `conclusion` пока не
сопоставляются с источником программно. Код студентов не запускается, а заявления
о фактическом выполнении тестов не являются результатом этой системы.

В Ollama передаётся JSON Schema без строковых `maxLength`: Ollama 0.19.0
преобразует большие значения в грамматику повторений, которую её парсер
отклоняет; это воспроизведено с `qwen2.5:7b-instruct`. Все ограничения длины
сохраняются в проверке результата Pydantic. Остальная структура схемы,
лимиты байтов ответа и выходных токенов также сохраняются.

## Проверка одного документа реальной моделью

Команда требует доступной Ollama, использует тот же pipeline, что HTTP, и печатает
только результат JSON. Из `apps/ml`:

```powershell
ml-evaluate C:/reports/lab.docx --title "Среднее арифметическое" --methodical-guide examples/methodical_guide.txt --grading-criteria examples/grading_criteria.txt
```

Поддерживаются также `--system-instructions` и `--reference-work`. Работа студента
должна быть PDF/DOCX; материалы могут быть PDF/DOCX/TXT. Веса и документы в Git не
добавляйте. Синтетические отчёты для первого ручного прогона:

```powershell
python examples/generate_samples.py C:/lab-assessment-fixtures
ml-evaluate C:/lab-assessment-fixtures/missing_empty_guard.docx --title "Среднее арифметическое" --methodical-guide examples/methodical_guide.txt --grading-criteria examples/grading_criteria.txt
```

Генератор создаёт пять случаев: корректное решение, отсутствующая обработка
пустого ввода, неверный знаменатель, другая тема и prompt injection. Manifest
содержит ожидаемые наблюдения, **не экспертные баллы**. Запишите замечания
преподавателя отдельно. Доля валидных JSON, ошибка баллов, обнаружение ошибок,
полезность комментариев, задержка и память — разные показатели. Смысл целевых
«75%» должен определить аналитик; эти примеры такую точность не подтверждают.

Для сравнения версий на фиксированных заданиях используйте
[набор оценки качества](evaluation/README.md): отдельные development/holdout,
настоящая генерация, метрики оценок и отдельная проверка достоверности замечаний.
Измеренные результаты от 2026-11-08 приведены в
[отчёте сравнения](../../docs/ml-grading-evaluation.md).

## HTTP-контракт

`POST /evaluate`, multipart/form-data. Поле `metadata` — JSON общей схемы
`assessment_contract.schemas.EvaluationRequest`, поле `submission` — файл работы.
Файлы материалов имеют имена категорий. Пример метаданных:

```json
{
  "attempt_id":"attempt-123",
  "lab_id":"lab-123",
  "title":"Среднее арифметическое",
  "description":null,
  "settings_version":1,
  "materials":{
    "methodical_guide":{"file_key":"methodical_guide"},
    "grading_criteria":{"text":"{\"criteria\":[{\"name\":\"Корректность\",\"max_score\":10}]}"}
  }
}
```

Ответ содержит только `score`, `max_score`, `conclusion`, `criteria`. Идентификаторы,
статус и время сохраняет backend. Ошибка:

```json
{"error":{"code":"DOCUMENT_NO_TEXT","message":"В документе нет доступного текста...","retryable":false}}
```

Повторяемые ошибки: занятый сервис, недоступная модель, сетевой сбой и тайм-аут.
OOM, повреждение документа, превышение контекста и повторно невалидный ответ не
маскируются оценкой. Невалидный результат получает максимум одну дополнительную
генерацию. Backend имеет собственный ограниченный повтор временных ошибок.

## Ограничения и эксплуатация

- До 20 MiB на файл, пяти файлов на запрос, 100 страниц PDF, 200 000 извлечённых
  символов и 32 MiB распакованного DOCX. Поля формы/общий объём также ограничены.
- Извлечение идёт в отдельном процессе: 20 секунд на документ, после тайм-аута
  процесс завершается. На Linux адресное пространство ограничено 1 GiB. В native
  Windows **нет жёсткого ограничения RSS дочернего процесса**; для недоверенных
  больших PDF предпочтителен контейнер с лимитом памяти. Проверка размера файла
  сама по себе не ограничивает потребление памяти PDF-парсера.
- Таблицы DOCX читаются вместе с абзацами. Изображения, скриншоты, текстовые поля
  Word и сложные формулы не распознаются; OCR отсутствует. Для смешанного PDF
  страницы без текста явно отмечаются. Код студентов не выполняется.
- В журнал пишутся ID попытки, длительность и код ошибки; документы, промпты,
  ответы модели и токены доступа не записываются. Ограничение промпта уменьшает
  риск injection, но не доказывает устойчивость модели — это отдельный ручной тест.
- Укажите одну реплику и один процесс ML; Ollama также должна иметь
  `OLLAMA_NUM_PARALLEL=1`. Постоянной очереди/БД на ML нет; восстановлением заведует backend.
- Для резерва можно выбрать `qwen3:1.7b-q4_K_M`: pipeline отключает thinking для
  обычных Qwen3. Нужны его собственный токенизатор и отдельная проверка качества.

Dockerfile собирается **из корня** репозитория:

```sh
docker build -f apps/ml/Dockerfile -t lab-assessment-ml .
```

В корневом Compose профиль `ml` запускает ML на Linux с
`ML_URL=http://ml:8001` для backend и
`OLLAMA_URL=http://100.81.179.101:11434` для обращения к Windows.
Отдельный профиль `ollama` нужен только для совместного размещения; тогда
`OLLAMA_URL=http://ollama:11434`. См. корневой README для GPU/CPU-профилей
и скачивания весов в отдельный volume.

## Автоматические проверки

После установки пакетов из корня репозитория:

```sh
python -m unittest discover -s apps/ml/tests -v
```

Тесты проверяют реальные парсеры PDF/DOCX/TXT, таблицы, кириллицу, дочерний процесс,
границы контекста, multipart, авторизацию, арифметику, соответствие цитат источнику,
вердикты, отсутствие шкалы, ошибки и ограниченный повтор. HTTP Ollama заменён
**заглушкой**; эти тесты не являются
измерением качества модели или производительности GPU.

Официальные источники: [модель Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507),
[тег Ollama](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M),
[JSON Schema](https://docs.ollama.com/capabilities/structured-outputs),
[настройки Ollama](https://docs.ollama.com/faq).
