# Лаб.АИ — frontend

React 19, TypeScript, Vite 8, Tailwind CSS 4 и React Router 7. Существующие компоненты дизайна Рафаэля используются и для демонстрации, и для работы с FastAPI. Сохранены цвета, локальный Manrope, SVG-иконки, основные блоки и адаптивная навигация.

## Запуск

Требуются Node.js 20.19+ в ветке 20 либо 22.12+ и npm 10+.

```sh
cd apps/frontend
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173/** и оставьте терминал работающим. В PowerShell при блокировке `npm.ps1` используйте `npm.cmd`. Перед `npm ci` остановите Vite: на Windows процесс может блокировать нативные зависимости. При занятом 5173 Vite не меняет порт автоматически; используйте уже работающий сервер или остановите его в исходном терминале.

FastAPI запускается отдельно по инструкции `apps/backend/README.md`. Frontend не запускает Docker, миграции, seed или Moodle.

```sh
npm run typecheck
npm run lint
npm run build
npm run preview
```

Preview доступен на **http://127.0.0.1:4173/**. Это локальная проверка сборки, не production-хостинг.

## Конфигурация API

По умолчанию запросы идут в `/api` на origin frontend. Vite dev и preview проксируют их на `http://127.0.0.1:8000`, поэтому различие CORS между `localhost` и `127.0.0.1` не мешает разработке. Backend не изменён.

Необязательные настройки из `.env.example` можно задать в `.env.local`:

- `VITE_API_BASE_URL=/api` — публичный адрес API для браузера.
- `API_PROXY_TARGET=http://127.0.0.1:8000` — адрес backend для Vite proxy; не передаётся в браузер.

Не помещайте JWT и другие секреты в Vite-переменные, исходники или документацию. Для production нужен reverse proxy `/api`; Vite proxy не входит в статическую сборку. При отдельном API origin требуется согласовать CORS на сервере.

## Два режима и вход

**Демонстрация** выбирается явно на экране подключения. Содержит прежние семь работ, переключение ролей, настройки в памяти и результат 82/100. Запросов к backend нет, файлы остаются в браузере. Перезагрузка возвращает к экрану подключения. При ошибке API автоматического перехода на mock нет.

**API** использует проверенный сервером JWT. В локальном dev-режиме вставьте действующий тестовый JWT без слова `Bearer` в поле подключения. Профиль проверяется через `/api/me`; лабораторная берётся из контекста того же токена. Самостоятельное декодирование JWT не даёт доступа к интерфейсу.

JWT хранится только в `sessionStorage` текущей вкладки, не в `localStorage`. При запрещённом storage сессия работает в памяти до перезагрузки. Ошибка 401 или истечение срока JWT завершает сессию. Для смены пользователя нажмите стрелку профиля «Сменить сессию» или «Завершить сессию» внизу страницы. Получение новых токенов выполняется вне frontend; seed автоматически не запускается.

Dev-поле ввода JWT отсутствует в production-сборке. Production принимает LTI launch-параметры `token` и `lab_id`: до создания Router они считываются и удаляются из URL через History API. Затем `/me` проверяет сессию и выбирается маршрут роли. Передача JWT через URL остаётся ограничением существующего backend-контракта; очистка URL не устраняет все риски такого способа передачи.

## Сценарии API

- **Преподаватель:** лабораторная, таблица попыток, серверная статистика, поиск, группы и пагинация. Строка соответствует попытке, не уникальному студенту. Сортировка по имени применяется к текущей странице и явно подписана. Неизвестные количество файлов и максимум балла не выдумываются.
- **Карточка:** загружается непосредственно по ID, включая прямой URL и перезагрузку. Файлы скачиваются авторизованным Blob-запросом. Критерии запрашиваются отдельно. Решение сохраняется только после успешного POST; ошибка сохраняет введённый комментарий. Для доработки комментарий обязателен, доступность кнопок учитывает `actions` backend.
- **Настройки:** загрузка материала возвращает `file_id`; текст и файл взаимоисключающие. GET сохранённых настроек отсутствует, поэтому форма обозначена как черновик. Частичное сохранение неизвестного серверного набора заблокировано. PUT разрешён только при заполнении всех четырёх материалов и подтверждении полной замены. Адресное DELETE одного материала также требует подтверждения. Удаление файла из черновика не удаляет серверный материал. Загруженный файл применяется только после PUT.
- **Студент:** история с пагинацией, выбор попытки, PDF/DOCX через выбор или drag-and-drop, загрузка на сервер, скачивание сохранённого файла и просмотр результата/комментария. Новая попытка не удаляет предыдущие.
- **Проверка:** после 202 выполняется опрос попытки и результата каждые 3 секунды, максимум около двух минут ожидания плюс время текущего запроса. Каждый запрос ограничен 30 секундами. Опрос прекращается при конечном статусе, сетевой ошибке, смене попытки или размонтировании; доступно ручное обновление.
- **Без ML:** `ai_failed` показывается как техническая недоступность проверки, а не ошибка студента. Фиктивные оценки и критерии в API-режим не попадают. Отправка преподавателю доступна только для `ai_checked` и `returned_for_revision` и подтверждается ответом сервера.

## Ограничения backend

1. Нет GET сохранённых настроек. Без него нельзя безопасно редактировать одну вкладку существующего набора.
2. Студенту недоступен полный контекст лабораторной: название берётся из проверенного launch-контекста; описание, срок и лимит не подменяются демонстрационными значениями.
3. В списке преподавателя нет максимума оценки и количества файлов; они уточняются в карточке, где доступны.
4. Нет строгой схемы критерия. Показываются только фактически полученные название, баллы, максимум и комментарий.
5. Студенческий ответ не содержит `teacher_submitted`. Подтверждённая отправка известна frontend только в текущей сессии; после перезагрузки предыдущая отправка не угадывается.
6. `actions` карточки запрещает изменение принятой работы, хотя POST review имеет другие ограничения. UI следует `actions`.
7. Подтверждено на живом backend: скачивание файла с кириллическим именем возвращает 500 из-за Content-Disposition. Скачивание DOCX с латинским именем работает; байты совпадают с PostgreSQL. Клиент показывает ошибку, не имитируя успешное скачивание.
8. Новые попытки получают `ai_failed`; публикация оценки в Moodle возвращает 501. ML и Outcomes не реализуются frontend.

## Структура

```text
src/api/                    — fetch-клиент, DTO, endpoints, преобразование данных
src/app/runtime.ts          — режим, JWT-сессия, приём и очистка LTI URL
src/app/SessionGate.tsx      — dev-подключение, отсутствие сессии, проверка роли
src/app/useDemoSession.ts    — состояние UI и изолированные источники demo/API
src/app/routes.tsx          — существующие React-маршруты
src/features/teacher/       — таблица, настройки, карточка и решения
src/features/student/       — загрузка, история, polling и результат
src/hooks/                  — запросы с отменой, операции, фокус, уведомления
src/components/             — общие layout и UI-компоненты
src/data/mockData.ts        — данные только Demo Mode
src/styles/                 — исходный дизайн и технические состояния
src/index.tsx               — точка входа
public/fonts/               — Manrope и лицензия SIL OFL
```

## Маршруты и размещение

Сохранены `/`, `/teacher`, `/teacher/settings`, `/teacher/submissions/:id`, `/student`, `/student/check` и неизвестный маршрут. В API-режиме корень ведёт на экран реальной роли; неподходящий маршрут перенаправляется на разрешённый. Backend независимо проверяет полномочия каждого запроса.

После нового входа неизвестный исходный URL направляется на главную страницу роли; `/index.html` также считается входной страницей. Допустимая прямая ссылка на карточку сохраняется. Неизвестные адреса при последующей навигации и восстановлении сессии по-прежнему показывают 404.

На ширине от 1200 px — исходный sidebar, 768–1199 px — компактная панель, ниже 768 px — выдвижное меню. Сохранены Escape, закрытие по фону, управление фокусом, Back/Forward и поддержка reduced motion.

BrowserRouter использует `import.meta.env.BASE_URL`. Для размещения под префиксом:

```sh
npm run build -- --base=/lab-assistant/
npm run preview -- --base=/lab-assistant/
```

Хостингу нужен SPA fallback для вложенных React URL. `/api` должен маршрутизироваться отдельно и не возвращать `index.html`. `FRONTEND_URL` backend должен указывать на корень frontend с соответствующим префиксом. Frontend Dockerfile, общий Compose и конфигурация Moodle не добавлялись.

## Проверка интеграции

Выполнены `npm run typecheck`, `npm run lint` и `npm run build`. Преподавательское чтение профиля, трёх seed-работ и статистики из PostgreSQL дополнительно подтверждено ручной проверкой команды.

**Реальный FastAPI и PostgreSQL, Chrome:** вход студента, история, существующий результат и отправка доступной попытки преподавателю; загрузка настоящих PDF/DOCX и сохранение `ai_failed`; прямое открытие карточки; повторное решение «На доработку» с сохранением исходного комментария и статуса; загрузка материала TXT; подтверждённый PUT полного набора исходных текстов. После PUT все восемь полей материалов сверены с БД — прежние значения сохранены. Также проверены скачивание DOCX, ошибка кириллического скачивания, смена/завершение сессии, восстановление после перезагрузки, запрет преподавательского маршрута студенту, мобильная навигация и Demo Mode без запросов к серверу.

JWT для проверок выпускались существующей функцией backend и использовались только в памяти. Seed повторно не запускался; данные не удалялись. В БД остались две новые тестовые попытки, загруженный материал и запись проверки преподавателем; сохранение настроек повысило версию без изменения содержимого.

**Отдельные проверки на подставленных HTTP-ответах:** ошибки HTTP, тайм-аут polling, истечение JWT, LTI-параметры, запись `file_id` в настройках и production-режим без dev-входа. Эти проверки не выдаются за операции с PostgreSQL.

**Остаётся непроверенным на живом API:** новое принятие работы (чтобы не менять исходные решения), применение загруженного файла в настройках вместо существующего материала, удаление материалов. Чтение настроек и полный контекст студента блокируются отсутствующим контрактом. Настоящий Moodle launch, ML и общий Docker Compose — следующие этапы.

Разовые браузерные скрипты, инструменты и снимки удалены после проверок. `.qa/`, `dist/`, `node_modules/` и локальные `.env` исключены из Git; это не поддерживаемый набор автотестов.
